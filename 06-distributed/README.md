# 分布式

> 后端架构核心。本目录按 **"为什么 → 三大块 → 怎么做"** 三层组织——从体系层面理解分布式,而不是死记技术名词。

## ★ 第一层:为什么需要分布式?

**单机有三个硬上限**:

| 维度 | 单机瓶颈 | 业务后果 |
| --- | --- | --- |
| **性能** | CPU / 内存 / 磁盘 / 带宽撑不住业务增长 | 慢、超时、雪崩 |
| **可用性** | 单点故障 = 全站不可用 | 机房挂 = 业务挂 |
| **弹性** | 不能动态扩缩容 | 大促扛不住业务洪峰 |

→ 必须 **多机协作 + 流量分摊 + 故障隔离**,这就是分布式系统三大问题域的来源。

## ★ 第二层:三大块解决什么问题?

| 块 | 解决问题 | 关键词 | 主要文件 |
| --- | --- | --- | --- |
| **🧱 分布式原理(协同)** | 多机协同不出问题 | CAP / 共识 / 事务 / 锁 / ID / 协调 | 01-05、09-10 |
| **⚡ 高性能设计(扛流量)** | 系统不被大流量冲垮 | 限流 / LB / 缓存 / 异步 / 削峰 | 06(限流)、07 + ../04-redis + ../05-mq |
| **🛡 高可用设计(扛故障)** | 部分服务挂了不影响用户 | 熔断 / 降级 / 重试 / 幂等 / 容灾 | 06(熔断/降级)、08 |

**因果关系(环环相扣)**:

```
🧱 原理是地基  → 没原理就无从谈协同(CAP / 共识是物理边界)
       ↓
⚡ 性能解决"忙的时候不挂" → 大流量来了能扛(限流 / 缓存 / 削峰)
       ↓
🛡 可用解决"挂了不影响用户" → 真挂的时候有兜底(熔断 / 降级 / 多活)
```

> **三块缺一不可**:只有原理没性能 = 单机式集群,只有性能没可用 = 平时快关键时刻挂,只有可用没原理 = 故障状态都不一致。
