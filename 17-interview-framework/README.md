# 17-interview-framework · 面试综合能力考察框架

> **本目录定位**:跨越单一技术领域的**元能力 / 考察框架 / 面试方法论**——区分"背八股"和"真做过 / 真想过系统"的人。
>
> 这里不讲具体技术(那是 01-16 目录的事),只讲**怎么考察 / 怎么作答 / 怎么判断深度**。
>
> 双重视角:既是**面试官**用的评估框架,也是**候选人**用的答题指南。

## 〇、为什么需要这个目录

> 跨多个目录的"元能力"以前散落各处——`09-ddd/09-three-models-mapping` 讲业务/领域/数据三层,`14-projects/` 讲项目讲述,`15-leadership/` 讲资深答法,但都是**领域内的视角**。
>
> 当你面试一个资深工程师,真正区分"P5/P6/P7"的不是某个技术点会不会,**而是能不能 "业务模型 → 系统设计 → 技术架构" 递进式表达**——这才是本目录要沉淀的。
